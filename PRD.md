# PRD — Portal Informasi DTSEN BPS Kota Tangerang

## 1. Project Overview

### Nama Proyek
**Portal Informasi DTSEN — BPS Kota Tangerang**

### Tujuan
Membangun website informasi publik yang membantu masyarakat awam, terutama pengguna smartphone, memahami:

- Apa itu DTSEN
- Apa manfaat DTSEN
- Data/variabel apa saja yang tercakup
- Apa itu desil
- Bagaimana memahami desil 1–10
- Hubungan DTSEN, desil, dan program bantuan sosial
- Bagaimana melakukan pembaruan data DTSEN
- Kanal resmi yang dapat digunakan masyarakat
- Pertanyaan umum terkait DTSEN

Website harus terasa seperti **layanan informasi publik yang ramah, sederhana, resmi, dan mudah digunakan**, bukan dashboard statistik yang rumit dan bukan landing page startup.

### Target Pengguna Utama
Masyarakat umum/warga, termasuk pengguna yang:

- tidak memahami istilah statistik
- menggunakan smartphone sebagai perangkat utama
- datang ke website untuk mencari jawaban secara cepat
- ingin mengetahui apa itu DTSEN
- ingin memahami desil
- ingin mengetahui hubungan desil dengan bansos/program
- ingin memperbarui data yang tidak sesuai
- membutuhkan akses jelas menuju kanal resmi

# 2. Sumber Konten Utama

## Sumber Utama Wajib

Dua infografis yang diberikan oleh pengguna harus menjadi **sumber utama struktur dan materi website**.

### Sumber 01 — Variabel dalam Pemutakhiran DTSEN

Materi utama:

- DTSEN sebagai basis data individu dan/atau keluarga yang memuat kondisi sosial ekonomi
- Identitas kependudukan
- Pendidikan
- Ketenagakerjaan
- Kepemilikan usaha

### Sumber 02 — Pembaruan Data DTSEN

Materi utama:

1. Pembaruan melalui SIKS-NG
2. Pembaruan melalui Cek Bansos
3. Pembaruan melalui Form BPS / Cek DTSEN
4. Informasi atau dokumen yang perlu disiapkan

### Aturan Konten Sumber Utama

- Jangan mengubah substansi kedua infografis.
- Jangan menghilangkan kategori utama dari kedua infografis.
- Jangan menambahkan fakta yang tidak dapat diverifikasi.
- Informasi tambahan mengenai DTSEN, desil, manfaat, bansos, atau mekanisme pembaruan harus berasal dari sumber resmi pemerintah.
- Apabila terdapat perubahan kebijakan, gunakan informasi resmi terbaru.
- Jangan mengarang angka, ketentuan, link, nama program, persyaratan, atau prosedur.

# 5. Anti-AI-Slop Design Rules

## WAJIB

- Desain terasa natural dan dirancang manusia.
- Gunakan whitespace secara proporsional.
- Gunakan komponen hanya ketika berguna.
- Pertahankan hierarki visual yang jelas.
- Gunakan ilustrasi yang konsisten.
- Gunakan warna secara terkontrol.
- Fokus pada keterbacaan dan navigasi.

## JANGAN

- Jangan menggunakan excessive gradient.
- Jangan menggunakan glassmorphism.
- Jangan menggunakan ilustrasi 3D.
- Jangan menggunakan neon color.
- Jangan menggunakan terlalu banyak floating blob.
- Jangan menggunakan terlalu banyak shadow.
- Jangan menjadikan semua elemen berbentuk pill.
- Jangan membuat card di dalam card di dalam card.
- Jangan menggunakan terlalu banyak warna dalam satu viewport.
- Jangan menggunakan typography futuristik.
- Jangan membuat animasi berlebihan.
- Jangan menggunakan parallax yang tidak diperlukan.
- Jangan menggunakan auto-carousel untuk konten utama.
- Jangan membuat desain terlalu simetris hanya agar terlihat "sempurna".
- Jangan menggunakan stock-photo secara acak.
- Jangan menambahkan elemen dekoratif tanpa fungsi.
- Jangan membuat website tampak seperti hasil generator landing page AI.

**Mobile-first.**

- Desktop

### Button

- ukuran cukup besar untuk disentuh
- spacing cukup
- tidak saling berhimpitan
- label jelas

### Text

- tidak terlalu kecil
- line-height nyaman
- paragraf pendek
- jangan memadatkan terlalu banyak informasi

### Layout

- single column pada mobile
- dua/three/four-column hanya ketika ruang mencukupi
- komponen harus dapat melakukan reflow dengan natural

### Jangan

Jangan sekadar mengecilkan layout desktop menjadi mobile.

Mobile harus menjadi pertimbangan desain sejak awal.

# 39. Final Instruction to Antigravity

> **IMPORTANT IMPLEMENTATION DIRECTIVE**
>
> Build this website as a public information service for ordinary Indonesian citizens, not as a technology-product landing page.
>
> **Bootstrap is mandatory as the primary UI/CSS framework.**
>
> Do not replace Bootstrap with Tailwind CSS, Material UI, Chakra UI, Bulma, Foundation, or another UI framework.
>
> Use Bootstrap's grid, responsive breakpoints, navbar, accordion, buttons, cards, containers, spacing utilities, and responsive utilities wherever appropriate.
>
> Use custom CSS only for project-specific visual refinement and styling that Bootstrap cannot reasonably provide.
>
> The final implementation must remain genuinely Bootstrap-based, not a custom CSS project that merely happens to include Bootstrap.
>
> The primary audience is smartphone users who may have little or no understanding of statistics, DTSEN, desil, or government terminology.
>
> Every design decision must prioritize:
>
> **clarity → readability → ease of use → accessibility → performance → aesthetics**
>
> Do not over-engineer.
>
> Do not invent facts.
>
> Do not add unnecessary features.
>
> Do not make the UI look AI-generated.
>
> Use the two supplied DTSEN infographics as the primary content and structural reference.
>
> Use the approved homepage mockup as the primary visual direction.
>
> Preserve the visual character of the approved illustration style.
>
> Keep the interface minimal, cheerful, official, human, trustworthy, and easy to understand.
>
> Use subtle interactions only.
>
> Make all external government links explicit with an external-link indicator.
>
> Build mobile-first and test carefully at approximately 360–430 px widths.
>
> Make the mobile experience a first-class design target, not a resized desktop page.
>
> Use accordion/expandable UI for short explanations such as the seven DTSEN variable categories. Do not create unnecessary pages for short content.
>
> Use separate detail pages only when the content genuinely requires longer explanation.
>
> Keep homepage content concise and scannable.
>
> Never use labels such as "Klik di sini" when a more descriptive action label is possible.
>
> The final website should feel like a carefully designed BPS public-service website created by an experienced human UI/UX designer — not an AI-generated template.
